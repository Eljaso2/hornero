# Task Workflows

## Standard Task Lifecycle

### 1. Planning
- Define clear acceptance criteria
- Break work into manageable subtasks
- Identify dependencies and blockers
- Estimate effort

### 2. Implementation
- Follow the style guide and conventions
- Write tests as you go
- Use the briefing for context and approach
- Commit regularly with meaningful messages

### 3. Review
- Self-review code before committing
- Check for style guide compliance
- Verify all tests pass
- Update documentation

### 4. Completion
- Ensure all subtasks are done
- Update relevant notes and briefings
- Archive or mark task as complete
- Document lessons learned

## Communication
- Use task tracking (README or notes) to keep team informed
- Document decisions and rationale
- Share blockers early
- Keep briefing updated for future work

## Code Review Checklist
- [ ] Code follows style guide
- [ ] Tests added/updated
- [ ] Documentation updated
- [ ] No unnecessary complexity
- [ ] Performance acceptable
- [ ] Security considerations addressed
