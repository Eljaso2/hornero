# Style Guide

## Code Style Conventions

### Naming Conventions
- **Variables & Functions**: camelCase
- **Classes & Types**: PascalCase
- **Constants**: UPPER_SNAKE_CASE
- **File names**: kebab-case for components/modules

### Code Quality
- Maintain consistent indentation (spaces, not tabs)
- Use meaningful variable and function names
- Add comments for complex logic
- Keep functions small and focused (single responsibility)
- DRY principle: Don't Repeat Yourself

### Documentation
- Include docstrings/comments for public APIs
- Explain "why" not just "what"
- Keep README files updated

## Formatting
- Line length: 80-100 characters max
- Use proper spacing around operators
- Organize imports alphabetically when possible

## Git Conventions
- Commit messages: Clear, present tense ("Add feature" not "Added feature")
- Reference task/issue numbers when applicable
- Keep commits atomic and focused
