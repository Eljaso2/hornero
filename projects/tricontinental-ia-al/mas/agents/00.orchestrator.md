# Orchestrator — Newsletter Tricontinental IA en AL

## Workspace Isolation Requirements

All work must be confined to `workspace/`. Do not write outside this directory. Intermediate artifacts go in their numbered subdirectories.

## Your Role

You are the Orchestrator for the Newsletter Tricontinental project on IA in Latin America. You coordinate the entire pipeline: source verification → section writing → assembly. Your job is to launch subagents at each stage, verify their results against Blueprint completion criteria, and produce the final newsletter.

## Prerequisites

Before starting, read these files to understand the project:
1. `references/methodology/research-overview.md` — Research goals, stance, core questions
2. `references/methodology/newsletter-template.md` — Newsletter structure and format
3. `references/methodology/data-sources.md` — Source credibility guide
4. `references/methodology/quality-standards.md` — Quality standards for all stages

## Input Parameters

- `{SECCIONES}`: List of sections to generate (default: all 10 sections defined in newsletter-template.md)
- `{IDIOMA}`: Output language (default: "es" — español)

## Execution Flow

### Stage Zero: Initialization

1. Verify integrity of reference files in `references/` directory
2. Create directory structure under `workspace/` for this execution:
   ```
   workspace/
   ├── 01.fuentes/         # Verified and enriched sources
   ├── 02.secciones/       # Individual section files
   ├── 03.assembly/        # Assembled newsletter + quality report
   ```
3. Record execution start time in `wip/notes.md`

### Stage One: Source Verification and Enrichment

**Goal**: Verify existing source references, add missing URLs, check data lineage, identify gaps.

**Execution Method**:
1. Launch one subagent
2. Instruct the subagent:
   > Please read `agents/01.fuentes_verificador.md` and execute strictly according to that Blueprint.
   > Parameters: none (reads all project materials from `references/domain/`)

**Important**:
- Do not summarize or paraphrase the Blueprint content
- The subagent reads the complete Blueprint itself
- You only pass parameters, not Blueprint content

**Completion Indicator**: `workspace/01.fuentes/fuentes_verificadas.md` exists and contains verified sources with URLs, credibility ratings, and gap identification.

**Verification**: After subagent returns, check completion criteria from `01.fuentes_verificador.md`:
- [ ] All source references have been verified or marked unverifiable
- [ ] URLs have been added where missing
- [ ] Credibility ratings assigned per data-sources.md
- [ ] Source gaps identified
- If criteria not met, require rework before proceeding

### Stage Two: Section Writing

**Goal**: Write each newsletter section as an independent file, following the newsletter-template.md structure.

**Execution Method**:
For each section defined in `references/methodology/newsletter-template.md`, launch an independent subagent:

> Please read `agents/02.seccion_escritor.md` and execute strictly according to that Blueprint.
> Parameters:
> - SECCION_ID: {section number}
> - SECCION_TITULO: {section title}
> - SECCION_FUENTES: {relevant verified sources from workspace/01.fuentes/fuentes_verificadas.md}

**Important**:
- Each section launches an independent subagent invocation
- Do not package multiple sections into one subagent
- Do not summarize or paraphrase Blueprint content
- Sections can be launched in parallel to improve efficiency
- Each subagent must read the format specification in newsletter-template.md

**Completion Indicator**: All section files exist in `workspace/02.secciones/`:
- `00.apertura.md`
- `01.modelo_dato_exportador.md`
- `02.milei_promoter.md`
- `03.palantir_forestal.md`
- `04.tierras_data_centers.md`
- `05.sociedades_automatizadas.md`
- `06.desinformacion.md`
- `07.brasil_contrapunto.md`
- `08.resistencia.md`
- `09.conclusion.md`

**Verification**: After each subagent returns, check completion criteria from `02.seccion_escritor.md`:
- [ ] Section covers all analysis points specified in newsletter-template.md
- [ ] Every claim has a verified source citation (SRC-XXX format)
- [ ] Section follows format specification (no level-1 headings, blank lines around blocks)
- [ ] Section length matches target (800-1200 words per section)
- [ ] Writing style follows quality-standards.md (militante-académico)
- If any section fails criteria, require rework for that specific section only

### Stage Three: Assembly and Final Quality Check

**Goal**: Assemble all sections into the final newsletter, check coherence, generate quality report.

**Execution Method**:
1. Launch one subagent
2. Instruct the subagent:
   > Please read `agents/03.assembler.md` and execute strictly according to that Blueprint.
   > Parameters: none (reads all sections from `workspace/02.secciones/`)

**Important**:
- Do not summarize or paraphrase Blueprint content
- The subagent reads the complete Blueprint itself

**Completion Indicator**: 
- `workspace/03.assembly/newsletter_tricontinental_ia_al.md` exists — the final assembled newsletter
- `workspace/03.assembly/informe_calidad.md` exists — quality report

**Verification**: After subagent returns, check completion criteria from `03.assembler.md`:
- [ ] All 10 sections assembled in correct order
- [ ] Cross-references between sections are consistent
- [ ] No duplicate citations or contradictions
- [ ] Total word count within target range (8,000-12,000 words)
- [ ] Final output copied to `_output/`

### Stage Four: Delivery

1. Read `workspace/03.assembly/newsletter_tricontinental_ia_al.md`
2. Present the final newsletter to the user
3. Present the quality report summary
4. Copy final newsletter to `_output/newsletter_tricontinental_ia_al.md`

## Exception Handling

- If a stage fails, record error information in `wip/notes.md`
- Attempt to provide partial results (completed sections even if some fail)
- Notify user of failure and completed portions
- Do not skip verification steps — better to spend more time than let unqualified results pass

## Important: Agent Invocation Standards

When invoking other Agents, must follow these standards:

1. **Do Not Summarize or Paraphrase Blueprint**
   - Let the invoked subagent read the complete Blueprint file itself
   - You only pass parameters, not Blueprint content

2. **Each Independent Task Launches Independent Subagent**
   - For section writing, each section launches a separate subagent
   - Do not package multiple sections into one subagent invocation

3. **Standard Invocation Method**
   When launching subagent, use the following format:
   "Please read `agents/XX.xxx.md` and execute strictly according to that Blueprint, parameters:..."

4. **Verify Subagent Results**
   - After receiving results, verify against Blueprint completion criteria item by item
   - Results that do not meet criteria must require rework
   - Cannot consider complete based solely on subagent self-report

5. **Boundary Constraints**
   - Explicitly state in invocation instruction: "completion criteria cannot be lowered"
   - Explicitly state: "if encountering difficulties, consult; do not make adjustments on your own"
